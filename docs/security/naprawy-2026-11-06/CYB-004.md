# CYB-004 — limity struktury XLSX przed wczytaniem openpyxl

Priorytet P1. Odtworzono dojście małego pliku do ogromnej ekspansji scalonych komórek; guard przerwał przed alokacją. Nie wywoływano OOM. Cel: niebezpieczny plik zostaje odrzucony przed eager load_workbook, a koszt preflight też ma granice.

## Pliki

- `services/commission-engine/src/goldis_commissions/importers/workbook.py`: polityka limitów, ZIP i strumieniowy preflight XML.
- `client_dictionary.py`: oba importery słownika muszą sprawdzać wejście przed wczytaniem; kontrola nie może istnieć wyłącznie w CLI.
- `cli.py`: wspólna ścieżka walidacji i kontrolowane kody błędów.
- `transport/process_supervisor.py`, `transport/app.py`: izolacja kosztu i sprzątanie procesów.
- `apps/api/src/features/commissions/commission-engine-client.ts`: ograniczony odczyt odpowiedzi i przerwanie transportu.
- Testy nowe: `tests/unit/test_workbook_limits.py`; rozszerzenia `test_dictionary_import.py`, `test_process_supervisor.py`, `tests/integration/test_transport.py`.

## Etap 1 — jedna polityka i sprawdzenie ZIP

1. [ ] Zdefiniować niemutowalną politykę WorkbookLimits. Obecne 16 MiB pliku, 256 MiB sumy ZIP, 2000 elementów i ratio 120 traktować jako dotychczasowe sufity; nie zwiększać ich przy naprawie bez pomiaru. Dodać budżety rzeczywiście odczytanych bajtów XML, węzłów i czasu.
2. [ ] Sprawdzać ścieżki, szyfrowanie, wymagane elementy, liczbę wpisów i duplikaty nazw ZIP. Nie wypakowywać archiwum do katalogu jako części walidacji. Deklaracje file_size sprawdzać razem z rzeczywistym zliczaniem bajtów odczytu; przerwać po limicie.
3. [ ] Zakazać DTD/encji i zewnętrznych odwołań; wybrać parser XML o jawnie wyłączonej obsłudze takich konstrukcji. Jeśli wymaga nowego pakietu, aktualizować pyproject i lock razem oraz audytować wersję w czasie implementacji.

## Etap 2 — walidacja struktury przed alokacją

1. [ ] Strumieniowo przejrzeć XML arkuszy, shared strings oraz metadane potrzebne do limitów. Zwalniać przetworzone elementy parsera; iterparse bez clear nie gwarantuje stałego kosztu pamięci.
2. [ ] Zliczać rzeczywiste komórki i indeksy wierszy/kolumn. Pole dimension jest wskazówką, nie jedynym źródłem prawdy. Odrzucać współrzędne poza zakresem Excela, odwrócone zakresy i niepoprawne zapisy.
3. [ ] Dla każdego merge policzyć powierzchnię arytmetycznie, bez iteracji po komórkach. Sumować ekspansję w całym skoroszycie; przekroczenie limitu przerywa przed openpyxl. Konserwatywna suma także dla nakładających się scaleń jest dopuszczalna, jeżeli kontrakt jest udokumentowany.
4. [ ] Ograniczyć definicje kolumn, maksymalne indeksy, liczbę węzłów i długość pojedynczego tekstu. Wymiar 25 000×64 sam pozwala na dużą alokację, dlatego potrzebny jest też limit łączny komórek.
5. [ ] Budżety startowe do kalibracji na fixture: maks. 40 arkuszy, 25 000 wierszy/arkusz, 64 kolumny, 10 000 dodatkowych komórek ze scaleń łącznie. Proponowane łączne 800 000 komórek i 32 MiB XML są wartościami projektowymi, nie zmierzonymi gwarancjami; potwierdzić je na limicie pamięci obrazu i istniejącym słowniku 653 pozycji.
6. [ ] Dopiero po preflight wykonać load_workbook. Sprawdzenia końcowe pozostawić jako drugą warstwę. Książkę zawsze zamykać przez try/finally. Nie przełączać mechanicznie read_only=True bez testów formatów procentów i wymaganej semantyki scaleń.
7. [ ] Dla importerów wołanych bezpośrednio z path zapewnić tę samą walidację bajtów. Unikać wyścigu „sprawdzono inny plik niż wczytano”: używać tej samej prywatnej, niezmiennej kopii albo tego samego bufora.

## Etap 3 — ograniczenie skutków błędu parsera

1. [ ] Supervisor: dodać konfigurowalny globalny limit aktywnych procesów; początkowo 1 na instancję silnika, do podniesienia po pomiarach. Ograniczyć także liczbę oczekujących żądań lub odmawiać po krótkim terminie uzyskania slotu. Semaphore z nieograniczoną kolejką nie zamyka kosztu oczekiwania.
2. [ ] Timeout obejmuje cały cykl procesu, w tym start i stdin.drain. Wyjątek readera stdout/stderr ma natychmiast zakończyć proces; nie czekać najpierw na process.wait z pełnym timeoutem.
3. [ ] W każdej ścieżce błędu/timeout/cancel: kill jeśli potrzebny, wait z krótkim limitem, anulowanie i zebranie readerów, usunięcie active pod lockiem oraz zwolnienie slotu. Token cancel nie może zakończyć nowszego procesu o tym samym executionId.
4. [ ] Limitować rzeczywiste bajty body przed pełnym parsowaniem i rzeczywiste bajty odpowiedzi przed JSON.parse. Zwracać kontrolowany kod: 413 limit transportu, 400/422 struktura pliku, 429/503 brak zasobu, 408 czas. Mapowanie API i UI uzgodnić w tym samym pakiecie.
5. [ ] Zachować obecne limity kontenera i nonroot. Weryfikować ich działanie w uruchomionym obrazie; konfiguracja YAML nie jest dowodem skuteczności.

Nie materializować ogromnego zakresu dla testu regresji. Ograniczone fixture wystarczą do pomiaru pamięci i czasu; pomiary wykonywać osobno dla preflight i całego procesu w obrazie Linux.

## Wdrożenie i zamknięcie

Brak migracji danych. Zmienić wersję parsera/obrazu i ewentualny kontrakt kodów błędów. Najpierw wdrożyć kompatybilny silnik z limitami, potem klienta, który je prezentuje. W razie problemu wyłączyć import nowych słowników, pozostawiając wcześniej opublikowane snapshoty.

Zamknięcie wymaga C004-01–10, pomiaru na ograniczonym obrazie i potwierdzenia, że żaden publiczny ani wewnętrzny importer nie omija preflight. Sam update openpyxl albo podniesienie pamięci kontenera nie zamyka luki.
