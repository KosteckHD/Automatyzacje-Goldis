# CYB-001 — walidacja edycji słownika i ochrona prototypu

Priorytet P1. Potwierdzono modyfikację Object.prototype w rzeczywistym serwisie z adapterami syntetycznymi. [Dowód i ograniczenia](../AUDYT_BEZPIECZENSTWA_2026-11-06.md#cyb-001--prototype-pollution-cwe-1321). Nie wykazano RCE. Cel: żadne wejście żądania nie może wskazać odziedziczonej właściwości jako komórki słownika.

## Pliki i zakres

| Plik | Zmiana |
|---|---|
| `apps/api/src/features/commissions/commissions.controller.ts` | Body traktowane jako unknown; brak odczytu body.revision przed walidacją |
| `apps/api/src/features/commissions/commission-dictionary-input.ts` — nowy | Jeden parser wejścia, typ wynikowy i zamknięte zbiory wartości |
| `apps/api/src/features/commissions/commissions.service.ts` | Parser na granicy serwisu, kontrola własnego klucza i struktury snapshotu |
| `apps/api/src/features/commissions/commission-dictionary-input.spec.ts` — nowy | Testy kontraktu i nieprawidłowych typów |
| `apps/api/src/features/commissions/commissions.dictionary.http.spec.ts` — nowy | Realny serwis za kontrolerem, istniejące guardy |

## Kontrakt po zmianie

| Pole | Dozwolona postać | Reakcja na inną wartość |
|---|---|---|
| body | Zwykły obiekt JSON, bez dodatkowych pól | 400 `INVALID_DICTIONARY_ENTRY` |
| revision | Dodatnia safe integer, bez konwersji string→number | 400 |
| agent | Dokładnie `Ola` albo `Maciek` | 400 |
| status | Jeden z obecnych statusów słownika | 400 |
| rate dla RATE | Liczba skończona w przedziale 0–100 | 400 `INVALID_COMMISSION_RATE` |
| rate dla innego statusu | Brak lub null; wartość wynikowa wyliczana przez serwis | Nieakceptowany nadmiar: 400 |

Przed zastosowaniem reguły rate sprawdzić aktualny payload w `apps/web/app/tools/commission-comparison/workspace.tsx`. Jeżeli frontend zawsze wysyła liczbę, dostosować go w tym samym pakiecie lub czasowo jawnie dopuścić wyłącznie zgodną wartość dla konkretnego statusu. Nie dopuścić niejawnej konwersji i nie ignorować dowolnych dodatkowych pól.

## Kroki implementacji

1. [ ] Dodać parser, który najpierw sprawdza obiekt, potem własne klucze i typy. Weryfikować agent przed jakimkolwiek lookup w snapshotcie. Zwracać nowy, jawnie zbudowany obiekt wyniku, bez kopiowania wszystkich właściwości wejścia.
2. [ ] Zmienić kontroler tak, aby przekazywał nieprzetworzone wejście do jednej walidowanej metody serwisu. Usunąć niebezpieczne założenie, że dekorator Body egzekwuje unię TypeScript. Aktualizować sygnatury i wszystkie wywołania razem.
3. [ ] W serwisie po walidacji i autoryzacji odczytać szkic w zakresie tenanta. Sprawdzić, że agents i komórka są poprawnymi obiektami i że agent jest własnym kluczem, np. przez Object.hasOwn. Sama kontrola truthy nie wystarcza.
4. [ ] Dla nieprawidłowej struktury zaszyfrowanego snapshotu zwrócić kontrolowany błąd integralności, np. 409 `COMMISSION_DICTIONARY_SNAPSHOT_INVALID`; nie mutować danych i nie zwracać treści snapshotu w błędzie.
5. [ ] Przejrzeć klucze rules pochodzące ze snapshotu. Przed zapisem/usunięciem walidować identyfikator reguły i własność właściwości; nie rozwiązywać problemu globalną zmianą Object.prototype. Tę kontrolę opisać jako hardening powiązany, bez ogłaszania nowej luki bez dowodu.
6. [ ] Zachować SessionGuard, execute, CSRF oraz odrębny grant edycji. Brak uprawnień nie może skutkować odczytem i ujawnieniem snapshotu przez komunikat walidacyjny.

## Testy i oczekiwane wyniki

| Test | Scenariusz | Oczekiwanie |
|---|---|---|
| C001-01 | Obaj agenci, RATE=0/100 i pozostałe prawidłowe statusy | Poprawny zapis wyłącznie wskazanej komórki |
| C001-02 | Klucze prototypu, constructor, nieznana nazwa | 400; zero save i audytu sukcesu |
| C001-03 | Null, tablica, obiekt zamiast agent, string rate, dodatkowy klucz | 400 bez TypeError/500 |
| C001-04 | Brak komórki lub zły agents w snapshotcie | Kontrolowany błąd integralności, zero mutacji |
| C001-05 | Wywołanie bezpośrednio serwisu z niepoprawnym body | Ta sama odmowa co przez HTTP |
| C001-06 | Rzeczywisty HTTP: anonimowy/brak execute/brak grantu/błędny CSRF | Odmowa na właściwej granicy, brak zapisu |
| C001-07 | Obcy tenant lub nieistniejący szkic | Brak odczytu obcego snapshotu; 404 według kontraktu |
| C001-08 | Deskryptory Object.prototype przed/po odrzuconym wejściu | Identyczne; niezwiązany obiekt nie dziedziczy nowych pól |

C001-08 wykonywać w jednorazowym procesie z timeoutem i przywróceniem prototypu w finally także przy awarii testu. Nie uruchamiać przeciwko współdzielonemu serwerowi.

## Wdrożenie, wycofanie i zamknięcie

Migracja DB nie jest potrzebna. Wdrożyć API i ewentualną kompatybilną zmianę formularza. Procesy API należy zrestartować, aby usunąć ewentualny wcześniej skażony stan pamięci; restart nie zastępuje naprawy. W razie regresji czasowo zablokować edycję słownika albo wycofać do wersji z zachowaną walidacją.

Zamknięcie: wszystkie testy C001 przechodzą na świeżym buildzie, publiczny endpoint nie omija parsera, a udokumentowany retest potwierdza brak zmian prototypu. CYB-002/003 pozostają odrębnymi warunkami nawet po naprawie tej luki.
