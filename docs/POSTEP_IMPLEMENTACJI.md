## PZU expiry i opóźniony resend — 2 października 2026

Po jednym zatwierdzeniu starego SMS przez użytkownika odczytano jeden widoczny `.errors_wrapper > span.errors` z tokenem `expired` i jeden widoczny `a#resend`. Zapis w `config/pzu-sms.observed.json` i obu przykładach, bez kodu i treści strony. `PortalSession.resendSmsCodeIfAvailable` czeka do 25 s na jedną dostępną akcję; brak po terminie jest błędem, nie przesłanką nowego logowania. Sprawdzanie jest lokalne w DOM, kliknięcie najwyżej raz; istniejący budżet API pozostaje bez zmian. Prawdziwy resend nie był klikany; błędny kod, zniknięcie starego błędu po resend i pełny modal/API/PZU nadal do odbioru. Aktualizacja kontenera workera po tej zmianie pozostaje do wykonania przed testem kontenerowym.

## Jak agent liczy postęp

W PowerShell, z katalogu repozytorium, agent może policzyć kroki bez czytania sekretów:

```powershell
$planPath = 'docs/PLAN_WYKONAWCZY_AUTOMATYZACJI.md'
$allSteps = Select-String -Path $planPath -Pattern '^- \[[ x]\] \*\*W\d+\.\d+\*\*'
$doneSteps = Select-String -Path $planPath -Pattern '^- \[x\] \*\*W\d+\.\d+\*\*'
$percent = if ($allSteps.Count) { [math]::Round(100 * $doneSteps.Count / $allSteps.Count, 1) } else { 0 }
"$($doneSteps.Count) / $($allSteps.Count) ($percent%)"
```

Po każdym pakiecie agent sprawdza także kompletność numerów: liczba przyjętych kroków w tej tabeli musi równać się liczbie `[x]` w odpowiedniej sekcji planu. Procent podaje z jedną cyfrą po przecinku. Nie wpisuje wyniku testu „zaliczony” na podstawie samego kodu wyjścia, jeśli test nie obejmuje wymaganego zachowania z opisu kroku.

## Meldunek po każdym kroku

Agent kończy pojedynczy krok krótkim meldunkiem:

```text
Krok: W?.?? — przyjęty / nieprzyjęty / zależny zewnętrznie
Zmiana: konkretne pliki i zachowanie
Dowód: komenda, wynik testu, sprawdzona granica usług
Postęp: przyjęte / 113 oraz przyjęte / liczba kroków pakietu
Bramka: nieoceniona / częściowa / zaliczona / wstrzymana zewnętrznie
Następny krok: W?.??; powód, jeśli pominięto numer
```

Po bramce pakietu agent dodatkowo uruchamia `npm test` i `npm run build`, a przy migracjach lub Compose wykonuje kontrolę odpowiedniej usługi. Gdy testy zawodzą, nie przenosi statusu pakietu na „zaliczona”.
